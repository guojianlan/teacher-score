## 零、当前执行约束

- `apps/web` 是 Next.js Web App 层，完整保留 SSR / RSC / SSG / ISR / CSR 能力；业务数据统一通过 `apps/backend` API 访问。
- `apps/backend` 是 Hono 后端应用，包含 HTTP API 入口和 pg-boss worker 入口。
- Better-Auth server handler 运行在 `apps/backend`，`apps/web` 只保留登录/注册 UI 和 auth client 调用。
- 业务 REST API 统一由 `apps/backend` 提供；`apps/web` 不直接访问数据库、不直接调用 LLM、不消费队列。
- 批改状态当前核心阶段使用轮询，不使用 Supabase Realtime。
- 所有 worker job payload 必须携带 `organizationId`，worker 查询必须按 `gradingId + organizationId` 双条件校验。

## 一、用户角色

| 角色 | 描述 | 阶段归属 |
|---|---|---|
| 老师（Teacher） | 主要使用者，完成批改、管理学生 | 当前核心阶段 |
| 机构主理人（Org Owner） | 创建机构、邀请老师 | 数据模型支持，UI 阶段 4+ |
| 机构管理员（Org Admin） | 教务管理、看全局数据 | 阶段 4+ |
| 普通成员（Member） | 受邀加入机构的老师 | 同 Org Owner |
| 家长（Parent） | 只读访问孩子学情 | 长期阶段 |

当前核心阶段默认所有老师注册后自动创建 personal organization，自己是 owner——用户感知不到 organization 概念，但底层支持。

## 二、用户故事

### Epic 1：认证与组织管理

**US-1.1** | 邮箱注册即用  
作为新老师，我希望用邮箱+密码注册后立即可以使用产品，不需要等待审核或选择机构。  
**验收**：注册 → 自动创建 personal org → 自动登录 → 进入 Dashboard，全程 < 60s。

**US-1.2** | Google 一键登录  
作为老师，我希望能用 Google 账号一键登录，省去记密码。  
**验收**：首次 Google 登录自动创建账号 + personal org。

**US-1.3** | 修改密码 / 忘记密码  
作为老师，我希望能修改密码或通过邮箱重置。  
**验收**：邮件链接有效期 30 分钟，重置后自动登出所有会话。

**US-1.4** | 邀请老师加入机构（阶段 4+）  
作为机构主理人，我希望能通过邮件邀请其他老师加入我的机构。  
**验收**：受邀老师 7 天内点击链接即可加入；可选角色 admin/member。

**US-1.5** | 切换组织（阶段 4+）  
作为属于多个机构的老师，我希望能在 UI 上切换当前活跃组织。  
**验收**：切换后所有数据视图（学生、试卷）自动按当前 org 隔离。

**US-3.3** | 模板审核 / 编辑

### Epic 5：LLM 批改

**US-5.1** | 异步批改  
作为老师，我希望提交后立刻看到"批改中"状态，不必傻等。  
**验收**：< 1s 返回 gradingId；状态从 pending → processing → completed。

**US-5.2** | 进度提示  
作为老师，我希望能看到批改进度（识别中 / 判分中 / 完成）。  
**验收**：提交批改后前端每 3 秒轮询 `GET /api/grade/:id/status`；状态从 pending → processing → completed/failed；completed/failed 后停止轮询；90 秒未完成时提示"仍在处理中，可稍后刷新"。

**US-5.3** | 失败重试  
作为老师，我希望批改失败时能一键重试。  
**验收**：失败后保留原图，点重试重新入队；自动重试上限 3 次。

**US-5.4** | 客观题全自动  
作为老师，我希望选择题、填空题完全无需介入。  
**验收**：选择题字符匹配；填空题数学/语义等价判断；准确率监控。

**US-5.5** | 主观题辅助  
作为老师，我希望主观题获得 LLM 的建议分 + 评分理由。  
**验收**：每道主观题展示建议分、理由、扣分点；老师可改分加评语。

**US-5.6** | 置信度标注  
作为老师，我希望低置信度的题目被高亮，方便重点复核。  
**验收**：LLM 输出每题 confidence (high/medium/low)；low 题黄色高亮；high 题默认隐藏复核。

**US-5.7** | 字迹不清处理  
作为老师，我希望字迹不清的题目被明确标出，而不是 LLM 瞎判。  
**验收**：LLM 检测到字迹不清时 confidence=low + 评语"字迹不清"；前端醒目提示。

## 四、非功能性需求

### 4.1 性能

| 指标 | 目标值 |
|---|---|
| 页面 LCP | ≤ 2.5s（P95） |
| API 响应（不含 LLM） | ≤ 500ms（P95） |
| LLM 批改端到端 | ≤ 60s（P95） |
| 图片上传 | ≤ 5s（P95，10MB 内） |
| Dashboard 首屏数据 | ≤ 1s（P95） |

### 4.2 可用性

- 目标 99% uptime（V1）
- 单点故障容忍：LLM API 失败 → 自动重试 3 次 + 提示用户
- 优雅降级：摄像头不可用时回退到文件上传

### 4.3 安全

**多租户隔离**（最高优先级）：
- 所有 DB 查询必须经过 `scopedDb(organizationId)` 封装
- Code review 红线：直接 import `db` 调用 → 禁止合并
- 每个表都有 `organizationId` 字段并加 index

**认证**：
- Better-Auth 管理 session
- session token 存 httpOnly cookie
- CSRF 防护（Better-Auth 内置）
- 密码 bcrypt 加盐存储（Better-Auth 默认）

**上传安全**：
- 只允许图片：image/jpeg, image/png, image/webp, image/heic
- 单文件 ≤ 10MB
- 服务端 MIME 校验（不仅是文件名）
- 图片元数据 strip（防 EXIF GPS 等）

**API 限流**：
- 每用户：≤ 100 req/min（除 LLM 批改）
- LLM 批改：≤ 10/min/user，≤ 100/day/user
- 全局 IP：≤ 1000 req/min（防爬）

**敏感数据**：
- LLM prompt 不传学生真实姓名（用 `[学生]` 占位）
- 日志不输出 PII（pino redact）
- 错误堆栈不返回到前端

### 4.4 合规

- 数据存储位置：Supabase 香港或新加坡区
- 用户数据可一键导出 / 删除
- 隐私政策 / 用户协议（V1 末上线）
- 未成年人数据：仅老师录入，不与学生本人交互
- ICP 备案：服务器本地，暂不需要

### 4.5 可观测性

- 结构化日志（Pino JSON）
- 关键事件埋点（PostHog）
- 错误监控（Sentry）
- LLM 调用监控：每次调用记录 token / 时长 / 成本 / 准确率信号

### 4.6 兼容性

| 范围 | 要求 |
|---|---|
| 桌面浏览器 | Chrome / Edge / Safari 最近 2 个版本 |
| 移动浏览器 | iOS Safari 15+ / Chrome Android 90+ |
| 屏幕尺寸 | 桌面 ≥ 1280×720，移动 ≥ 375×667 |
| 摄像头 | 支持 getUserMedia 的浏览器 |
| 网速 | 4G+ 可用，3G 降级 |

### 4.7 国际化（不在当前核心阶段范围）
- 当前中文界面
- 后续视用户分布决定是否加英文

### 4.8 技术执行约束

| 约束 | 要求 |
|---|---|
| Web 层 | `apps/web` 可使用 SSR/RSC/SSG/ISR/CSR，但业务数据通过 backend API 获取 |
| API 层 | 业务 REST API 统一在 `apps/backend` |
| Auth | Better-Auth server handler 在 `apps/backend`，不是 Next.js Route Handler |
| Worker | `apps/backend/src/worker.ts` 是唯一 pg-boss consumer 入口 |
| 进度更新 | 当前核心阶段使用 3 秒轮询，不使用 Supabase Realtime |
| 存储 | 生产默认 Supabase Storage；local storage 仅用于 dev/test |
| 多租户 | `organizationId` 是租户边界；业务表必须带 `organizationId` index |

## 六、验收标准与测试策略

### 6.1 单元测试覆盖率目标
- 工具函数（lib/）：≥ 80%
- 数据访问层（scopedDb）：≥ 90%
- AI grader 核心逻辑：100%（用 fixture）

### 6.2 集成测试
- Auth 流程：注册 → 登录 → 改密 → 登出
- 批改流程：上传 → 入队 → worker 消费 → 结果写入
- 多租户隔离：A 老师不能访问 B 老师的学生

### 6.3 E2E 测试（Playwright）
- 阶段 1 关键路径：登录 → 加学生 → 上传/拍照 → 批改 → 轮询完成 → 改分
- 阶段 3 关键路径：登录 → 加学生 → 批改 → 错题本 → 导出 PDF
- 阶段 4 关键路径：电脑端发起 + 手机端拍照联动

### 6.4 准确率测试（独立流程）
- Fixture 集：每科 20 张真实试卷（含答案）
- 阶段 1 必须先完成数学、英语 fixture；阶段 2 补齐语文、物理、化学 fixture
- 每次 prompt 更新跑对应学科 fixture；准确率衰退 > 5% 不可发布
- Bad case 入库，专门 prompt 调优
- 发布前由开发者本地运行准确率脚本；进入 CI 后，prompt/schema 变更必须自动跑对应学科回归
- 每科输出：客观题准确率、主观题建议分偏差、高置信度题老师改分率、低置信度召回样例
