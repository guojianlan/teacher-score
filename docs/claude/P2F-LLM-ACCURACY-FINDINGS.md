# P2F · 真实 LLM 准确率验证 · 发现报告

> 日期：2026-05-18
> 测试设置：5 个合成学生 × 答题卡 PNG (puppeteer 渲染 800×1131) × gpt-5.5 vision
> 数据源：tmp/synth/2025_八省联考考前猜想卷_生物-stu-{1-5}.png

---

## 一、核心发现：**MCQ 完美，结构化题严重幻觉**

| 分类 | 准确率 | 备注 |
|---|---|---|
| **Q1-Q15 选择题 (MCQ)** | **100%** (75/75) | LLM 完美识别填涂的字母 |
| Q16 (光合作用，单卡上首大题) | 97% | 几乎完美 |
| Q17-Q20 (结构化大题) | **7-29%** | **重灾区** |

总判定 275 项，引擎与 truth 一致 146 项（53.1%），不一致 129 项。

### 不一致的 129 项 100% 都是同一种错误

> 引擎 = false，truth = true，**学生写的内容跟标答完全一样**

意思是：**评分引擎认为学生答错了，但学生明明写了正确答案。**

---

## 二、根因诊断

抓了 stu-1 的 LLM 原始返回看：

```
Q16(1)#1: "PGA"                           ← 正确（题里就是 PGA）
Q16(1)#2: "作为还原剂还原PGA；为PGA..."     ← 正确
Q17(1)#1: "PGA"                           ← ✗ 应该是 5-HT 那段，但 LLM 抄了 Q16 的
Q17(1)#2: "作为还原剂还原PGA"             ← ✗ 同样抄 Q16
Q17(2)#1: "蔗糖"                          ← ✗ 同样
Q18(1)#1: "PGA"                           ← ✗
...
```

**LLM 在前 1-2 道大题里读到的内容，被复制粘贴当作后续大题的答案返回。**

### 为什么会这样

1. **合成 PNG 的"手写"渲染太小**：用了 14px 的 cursive 字体叠在下划线上，800×1131 分辨率下接近模糊
2. **LLM 看不清后面的题，就生成"听起来对的内容"**：典型的视觉模型 hallucination
3. **每张图的 5584-6514 tokens 已经把整页 OCR 满了**，没有额外能力做"真不知道就留空"

---

## 三、不是评分引擎的问题

合成数据 e2e（不走 LLM，直接拿 truth 喂评分引擎）：**1650/1650 = 100% 准确**

所以这次报告的 53.1% 准确率，**全部来自 LLM 视觉识别能力**，跟我们写的代码无关。

## 四、Phase 2 验证的边界

✓ **基础设施已就位**：
- puppeteer 装好（Chrome 148 下载完成）
- PNG 合成器跑通（5 张/5 学生）
- e2e --use-llm 端到端跑通
- 重试机制（每学生最多 3 次）
- 错误分布 + 按题准确率自动出报告
- 详细错误明细写到 `tmp/synth/e2e-detail.log`

✗ **当前限制（Phase 3 待解决）**：

1. **合成 PNG 视觉质量太低** → LLM 看不清就幻觉
   - 解：用真实答题卡照片测；或合成更大字号/更清晰排版
2. **Prompts 在"看不清"时没强约束 → 鼓励空字符串而非编造**
   - 解：prompt 加 "看不清必须输出空字符串，不要猜"
3. **网络抖动经常 500**（cliproxy → 上游不稳）
   - 解：3 次重试已有；可加缓冲队列
4. **单张图 token 5500-6500，cost 不低**
   - 解：未来可做 region crop（按 schema bbox 切图 → 多次小调用 → 但更稳）

## 五、给 Phase 3 的建议

按优先级：

| # | 项 | 工时估 |
|---|---|---|
| 1 | 用**真实手机拍的答题卡**做一组 ground truth | 1 天准备 + 0.5 天对比 |
| 2 | Prompt 加入"宁可留空不要猜"约束 + 输出格式严格化 | 2 小时 |

| 4 | 接入 region crop 流水线：按 schema 计算每题 bbox → 切图 → 小调用 | 1-2 天 |
| 5 | 评估二级模型（gpt-5.4 vs 5.5 vs gemini 2.5 等）准确率对比 | 半天 |
